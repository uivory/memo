# 디자인 체크

Figma 프레임 링크(`$ARGUMENTS`)를 읽고, AI가 이 시안을 코드로 옮길 때 헷갈리지 않는 구조인지 채점한다. 결과는 디자이너가 읽는다. 개발 용어보다 Figma 화면에서 쓰는 말로 쓴다.

## 1. 링크 읽기

`figma.com/design/{fileKey}/...?node-id=X-Y`에서 `fileKey`와 `nodeId`를 꺼낸다. `nodeId`의 `X-Y`는 `X:Y`로 바꾼다.

## 2. Figma 정보 가져오기

Figma 커넥터가 세션을 요구하면 `create_session`부터 부른다. 그다음 두 도구를 **동시에** 부른다.

- `get_design_context`: 생성 코드, 스크린샷, 컴포넌트 설명, 스타일. `disableCodeConnect: true`, `clientLanguages: "unknown"`, `clientFrameworks: "unknown"`으로 부른다
- `get_metadata`: 레이어 구조와 레이어 종류(frame, instance, text 등)

## 3. 네 항목 채점

항목마다 5점에서 시작한다. 감점 목록의 줄마다, 걸린 곳이 한두 곳이면 1점, 세 곳 이상이거나 화면 전체에 퍼져 있으면 2점을 뺀다. 0점보다 낮아지지는 않는다. 근거는 받은 정보에서만 찾는다.

- 레이어 종류는 `get_metadata`에서 본다 (instance는 컴포넌트 인스턴스, frame은 일반 프레임)
- 텍스트 스타일과 컴포넌트 설명은 `get_design_context` 결과 끝의 스타일 목록과 컴포넌트 설명 목록에서 본다. 목록에 없으면 없는 것이다
- 받은 정보로 판단할 수 없는 것만 "확인 못 함"에 적는다

### A. 레이어 이름

- `Frame 123`, `Group 4`, `Rectangle 7` 같은 자동 이름이 남아 있다
- 같은 단계에서 역할이 다른 요소들이 같은 이름을 쓴다 (목록에서 반복되는 항목은 괜찮다)
- `Text`, `Icon`, `Image`처럼 역할이 드러나지 않는 이름이 있다
- 글자 레이어 이름이 긴 문장 그대로다

### B. 오토레이아웃

- 묶음 안의 요소를 오토레이아웃 없이 좌표로 놓았다
- 간격을 gap이나 padding 대신 빈 상자로 만들었다
- 카드 위에 올려 둔 글자처럼, 함께 움직여야 할 요소가 묶음 밖에 있다

### C. 변수와 스타일

- 색이 변수 없이 값(`#3b7bf6`)으로 들어 있다 (생성 코드에 `var(--…)`가 없다)
  - 글자 일부에만 다른 색을 준 곳(`<span>`)은 Figma에서 변수에 연결해도 생성 코드에 값으로만 나온다. 같은 값이 생성 코드의 다른 곳에서 변수(`var(--color-primary,#3182f6)`)로 쓰였으면 감점하지 않고 "확인 못 함"에 적는다
- 간격이나 모서리가 변수 없이 숫자로만 들어 있다
- 글자에 텍스트 스타일이 없다
- 한글 글자의 글꼴이 Inter처럼 한글이 없는 글꼴이다

### D. 컴포넌트

- 같은 모양이 여러 번 나오는데 인스턴스가 아니다 (메타데이터에 instance가 아니라 frame으로 나온다)
- 버튼처럼 컴포넌트여야 할 요소를 사각형과 글자로 따로 그렸다
- 눌림, 비활성 같은 상태를 variant가 아니라 따로 그린 프레임으로 만들었다

## 4. 우리 팀 기준

팀마다 다른 규칙은 여기에 한 줄씩 더한다. 줄 끝 괄호에 감점할 항목(A~D)을 적는다. 이 줄도 3단계와 같은 방식으로 감점한다.

- (아직 없음)

## 5. 결과 보여 주기

프레임마다 아래 모양으로 짧게 쓴다. 프레임을 여러 개 받으면 프레임마다 반복한다.

**{프레임 이름}: {합계} / 20**

| 항목 | 점수 | 깎인 이유 |
|---|---|---|
| A. 레이어 이름 | ? / 5 | 걸린 줄과 레이어 위치. 없으면 비운다 |
| B. 오토레이아웃 | ? / 5 | |
| C. 변수와 스타일 | ? / 5 | |
| D. 컴포넌트 | ? / 5 | |

**먼저 고칠 것** (점수에 영향이 큰 순서로 3개까지)

1. {레이어 위치}: 무엇이 문제인지, AI가 구현하면 어떻게 틀어지는지, Figma에서 고치는 법

**잘한 점**: 한두 줄

**확인 못 함**: 받은 정보로 판단하지 못한 것 (없으면 뺀다)

## 6. Figma에 주석 남기기 (요청할 때만)

주석으로 남겨 달라고 하면 5단계 결과를 보여 준 뒤 `use_figma`로 Figma에 주석을 단다. 레이어, 색, 크기 같은 디자인은 바꾸지 않는다. `use_figma`를 쓰기 전에 Figma 공식 스킬(figma-use)을 읽는다.

- 분류는 `design-check` 하나를 쓴다. 파일에 없으면 빨강으로 만든다(`figma.annotations.addAnnotationCategoryAsync({ label: "design-check", color: "red" })`).
- 깎인 줄마다 걸린 레이어에 주석을 단다. 첫 줄은 `**B −2 · 누르는 곳 44px**`처럼 항목, 점수, 걸린 기준이고, 둘째 줄부터 무엇이 문제인지와 Figma에서 고치는 법을 한두 문장으로 쓴다(`labelMarkdown`). 우리 팀 기준에 걸린 줄은 첫 줄 끝에 `[팀 기준]`을 붙인다.
- 채점한 프레임에도 요약 주석을 하나 단다. 합계, 항목별 점수, 먼저 고칠 것 한 줄이다.
- 다시 달 때는 그 프레임 안의 `design-check` 주석만 지우고 새로 단다. `node.annotations`는 통째로 바뀌므로, 다른 분류나 다른 사람이 단 주석은 남긴 채 더한다.
- 인스턴스 안쪽 레이어에 달리지 않으면 가장 가까운 바깥 레이어에 달고, 내용에 원래 레이어 이름을 적는다.
- 끝나면 주석을 단 레이어 수를 알려 준다.

## 문제가 생기면

- 링크에서 `fileKey`나 `nodeId`를 찾지 못하면: 프레임을 선택한 채 복사한 링크를 달라고 한다
- 도구가 오류를 내면: 오류를 그대로 알리고, 이 파일을 열 수 있는 계정으로 Figma 커넥터가 연결됐는지 확인하게 한다
- 프레임이 아니라 컴포넌트 링크면: 그 사실을 알리고 그 컴포넌트가 쓰인 프레임 링크를 달라고 한다
- 주석을 달지 못하면(보기 권한만 있는 파일 등): 그 사실을 알리고, 채점 결과는 대화에 그대로 있다고 말한다
